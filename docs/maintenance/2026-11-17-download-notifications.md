# 2026-11-17：下载失败通知与错误诊断

## 问题与修复

多个近期下载任务失败时，右下角会不断重复显示“下载失败”。下载监视器每 1.5 秒轮询一次；成功任务使用 `dlSeen[job.id]` 去重，失败任务却只排除最后提示的任务 ID。两个失败任务便会轮流通过筛选，直到离开五分钟通知窗口，看起来像程序无响应。

失败通知改用相同的逐任务状态记录。每个失败任务仅提示一次，任务重新排序、成功通知插入和后续轮询都不会重新提示旧错误；新失败仍正常显示。同步更新静态脚本版本，避免界面复用旧脚本。

下载引擎在重试耗尽时原来丢弃底层异常，只返回“无法连接服务器或服务器无响应”。现在保留最后一次异常原因，帮助区分 HTTP 状态、连接或 TLS 等错误。保留原重试、并发和下载行为，不因通用错误提示猜测网络原因或更改全局代理。

## 证据边界

本次现场可以确认多个任务在收到数据前失败，但旧记录没有保存底层异常。随后使用相同引擎重试一个失败链接并完整下载成功；有限探测也收到有效的部分响应。这证明测试时连接可用，不能据此倒推出此前故障的具体原因，亦不能宣称所有网络故障均已修复。

诊断资料中的签名 URL、Cookie、个人下载历史和配置仅在本地读取，不进入源码提交、维护说明或发布附件。
